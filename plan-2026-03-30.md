# Implementation Plan: Asian Weather Shadow Tracker

## Goal

Build a shadow-mode data collection system that validates or kills the Asian
weather confirmation edge within 14 days. Two files: `run_asian_weather_shadow.py`
(main script, ~500 lines) and `src/calibration/emos.py` (~200 lines). Run via
cron every 10 minutes. No real trades, no capital at risk.

## Scope

**In:**
- `run_asian_weather_shadow.py` — main script at repo root
- `src/calibration/emos.py` — EMOS training and inference module
- `src/calibration/__init__.py` — package init
- `data/asian_weather_shadow/` — output directories (snapshots, oracle_triggers, forecasts, shadow_trades, resolutions)
- launchd plist for 10-minute cron scheduling

**Out:**
- Live trading, paper trading, or Polymarket order placement
- Helsinki server deployment (deferred — laptop-first)
- NO-harvesting CLOB depth analysis (Bundle 3 — post-collection)
- Changes to existing US weather validation code
- Changes to command-center

**Surfaces:** prediction-markets-research repo only. Read-only API calls to Polymarket, aviationweather.gov, Open-Meteo. No write access to any external system.

## Phases

### Phase 1: EMOS Calibration Module (`src/calibration/emos.py`)

Build the probability model first — everything else depends on it.

1. Create `src/calibration/__init__.py` (empty)
2. Create `src/calibration/emos.py` with:
   - `CITIES` config dict (8 cities with ICAO, lat, lon, tz)
   - `fetch_ensemble_forecast(lat, lon)` — call Open-Meteo ensemble API for IFS + AIFS daily max members (50+50)
   - `fetch_historical_actuals(lat, lon, tz, days)` — call Open-Meteo archive API for observed daily highs
   - `compute_naive_gaussian(ifs_members, aifs_members)` — return (mean, std) from pooled ensemble spread (bootstrap phase)
   - `train_emos(training_pairs)` — CRPS-minimized 5-parameter fit via scipy L-BFGS-B. Returns (a, b, c, d, e) per station
   - `emos_predict(params, ifs_mean, aifs_mean, ifs_var)` — return calibrated (mean, variance)
   - `bin_probabilities(mean, variance, bin_edges)` — integrate Gaussian PDF over each 1°C bin. Return dict of bin→probability
   - `bayesian_update(emos_mean, emos_var, metar_temp, forecast_temp_at_hour)` — shift mean by observed delta, return updated (mean, var)
3. Add `crps_loss(params, training_data)` internal function for optimization target
4. Unit test: verify `bin_probabilities` sums to ~1.0 for a known Gaussian

### Phase 2: Data Fetchers (inline in main script)

5. `fetch_polymarket_event(city_slug, target_date)` — Gamma API slug-based fetch, return list of 11 bins with prices, active/closed status, CLOB token IDs
6. `fetch_metar(icao_ids)` — aviationweather.gov bulk METAR fetch, return dict of station→(temp_c, raw_metar, obs_time)
7. `fetch_taf_tx(icao_ids)` — aviationweather.gov TAF fetch, extract TX groups, return dict of station→(tx_c, tx_time)
8. `build_weather_slug(city_slug, target_date)` — construct Polymarket event slug (pattern: `highest-temperature-in-{city}-on-{month}-{day}-{year}`)

### Phase 3: Shadow Trade Logic

9. `evaluate_yes_picking(bin_probs, bin_prices)` — if EMOS top-1 bin price < EMOS probability AND price < $0.25, return shadow trade entry
10. `evaluate_no_harvesting(bin_probs, bin_prices)` — for each bin where EMOS prob < 0.01 AND market YES price > $0.02, return shadow NO entry
11. `detect_bin_deaths(current_bins, previous_bins)` — compare snapshots, identify bins that transitioned from >$0.001 to $0.00, compute Delta_T against METAR
12. `detect_confirmation(current_bins, previous_bins)` — identify bins crossing $0.80 threshold

### Phase 4: State Management and Persistence

13. `load_previous_snapshot(city, target_date)` — read latest JSONL entry for this city/date
14. `save_snapshot(snapshot_record)` — append to `data/asian_weather_shadow/snapshots/{date}.jsonl`
15. `save_shadow_trade(trade_record)` — append to `shadow_trades/{date}.jsonl`
16. `save_oracle_trigger(trigger_record)` — append to `oracle_triggers/{date}.jsonl`
17. `save_forecast(forecast_record)` — write to `forecasts/{date}.json`
18. Ensure all output directories exist on first run (`os.makedirs(..., exist_ok=True)`)

### Phase 5: Resolution and Metrics

19. `check_resolved_markets(target_date)` — fetch yesterday's Polymarket events, identify winning bin per city, compute shadow trade P&L
20. `save_resolution(resolution_record)` — write to `resolutions/{date}.json`
21. `update_metrics()` — read all resolutions, compute running accuracy, P&L, Delta_T stats, per-region breakdown. Write to `metrics.json`
22. `update_readiness()` — evaluate kill/promote criteria against metrics. Write to `readiness.json`

### Phase 6: Main Loop and CLI

23. `main()` — orchestrate: determine target date, for each city: fetch data, compute probs, evaluate trades, detect events, save. Then check resolutions, update metrics.
24. Add `argparse` CLI: `--once` (single run), `--resolve-only` (just check resolutions), `--metrics` (print current metrics), `--city` (single city for debugging)
25. Add logging with `loguru` (already in repo dependencies)

### Phase 7: Scheduling

26. Create launchd plist at `~/Library/LaunchAgents/com.prediction.weather-shadow.plist` — runs every 10 minutes, 00:00-16:00 UTC, with `caffeinate` wrapper
27. Test: load plist, verify invocation fires, check JSONL output

## Dependencies

- Phase 2-6 depend on Phase 1 (EMOS module must exist for bin probability computation)
- Phase 3 depends on Phase 2 (needs fetchers)
- Phase 4 depends on Phase 3 (needs trade/trigger records to persist)
- Phase 5 depends on Phase 4 (needs persisted data to aggregate)
- Phase 6 depends on all above
- Phase 7 depends on Phase 6 (needs working script to schedule)

Linear chain: **1 → 2 → 3 → 4 → 5 → 6 → 7**

## Risks

- **LOW:** EMOS naive Gaussian underperforms during bootstrap (days 1-7). Mitigated: shadow-only, no real capital. Accuracy improves as training data accumulates.
- **LOW:** Open-Meteo API rate limit hit at 10-min polling (10K/day limit, we use ~150/day). Large margin.
- **LOW:** Polymarket Gamma API returns malformed JSON for some cities (seen during this session — `strict=False` needed). Mitigated: use `json.loads(raw, strict=False)` everywhere.
- **LOW:** METAR station temporarily offline. Mitigated: skip city, log gap, continue.
