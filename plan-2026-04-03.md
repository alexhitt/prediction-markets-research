# Implementation Plan: Asian Weather Bundle A — EMOS Calibration + Fetch Resilience

## Goal

Train EMOS parameters for all 8 cities using hindcast ensemble data + archive actuals, add retry logic and sane fallback to forecast fetching, and wire an auto-retrain trigger. This makes the shadow tracker's bin probabilities trustworthy so the kill/promote gate can produce real metrics.

## Scope

**In:**
- `src/calibration/emos.py` — new `fetch_hindcast_ensemble()`, `assemble_training_data()`, `train_all_cities()` functions; retry logic in `fetch_ensemble_forecast()`
- `run_asian_weather_shadow.py` — `--train` CLI command, last-known-forecast fallback in `process_city()`, weekly auto-retrain in `run_once()`
- `data/asian_weather_shadow/emos_params/*.json` — 8 param files created by training

**Out:**
- Bayesian update changes (Finding #4 — deferred to Bundle B)
- Yes-picking or NO-harvesting strategy changes (Finding #5, #6 — deferred to Bundle B)
- Delta_T implementation (Finding #7 — deferred to Bundle B)
- Storm Chaser V1 bot (separate system in command-center)

## Phases

### Phase 1: EMOS Training Pipeline

Build the data assembly and training functions in `src/calibration/emos.py`.

1. Add `fetch_hindcast_ensemble(lat, lon, past_days=10)` — calls ensemble API with `past_days` param, returns `Dict[str, Tuple[List[float], List[float]]]` mapping date strings to `(ifs_members, aifs_members)`. Uses the same `ecmwf_ifs025` and `ecmwf_aifs025` models as the existing `fetch_ensemble_forecast()`.

2. Add `assemble_training_data(city_slug, cfg, emos_dir, forecasts_dir, resolutions_dir)` — combines three data sources into `List[TrainingSample]`:
   - **Local forecasts + resolutions:** read `forecasts/{date}.json` and `resolutions/{date}.json`, match by city + date
   - **Hindcast + archive:** call `fetch_hindcast_ensemble()` for ensemble members, call `fetch_historical_actuals()` for observed daily highs, match by date
   - Dedup by date (local takes priority over hindcast for overlapping days)
   - Return list of `TrainingSample(ifs_mean, aifs_mean, ifs_var, actual_high)`

3. Add `train_all_cities(emos_dir, forecasts_dir, resolutions_dir)` — iterates over `CITIES`, calls `assemble_training_data()` then `train_emos()` for each. Validation gate: only save params if trained σ (sqrt of `d + e * median_ifs_var`)) > naive σ (ensemble stdev * 1.3). Log results per city: samples used, CRPS, fitted params, σ comparison.

4. Expose `--train` CLI command in `run_asian_weather_shadow.py` `main()` — calls `train_all_cities()` and prints results.

5. **Validate:** Run `python run_asian_weather_shadow.py --train` and verify:
   - 8 JSON files created in `emos_params/`
   - Each city trained on >=7 samples
   - Fitted σ > naive σ for each city
   - CRPS is finite and reasonable

### Phase 2: Forecast Fetch Resilience

Make the ensemble forecast fetching robust against transient API failures.

6. In `fetch_ensemble_forecast()` (emos.py ~line 80): wrap each model fetch in a retry loop (1 retry, 5s backoff). Add explicit `logger.warning()` on failure (replacing the bare `except pass` at line 111).

7. In `process_city()` (run_asian_weather_shadow.py ~line 635-684): replace the `mean, variance = 15.0, 9.0` fallback with a `load_last_known_forecast(city_slug, forecasts_dir)` call that reads the most recent forecast file for this city. Keep the 15.0/9.0 as a last-resort fallback only if no forecast file exists at all (true cold start). Log when the last-known fallback is used.

8. **Validate:** Temporarily break the ensemble API URL in a test run and verify:
   - Warning is logged on fetch failure
   - Last-known forecast is loaded instead of 15.0°C default
   - Shadow trades still execute with reasonable bin probabilities

### Phase 3: Auto-Retrain Trigger

Wire automatic retraining so EMOS params improve as data accumulates.

9. In `run_once()` (run_asian_weather_shadow.py ~line 789): after the main city loop, add an auto-retrain check:
   - Trigger if: any city's `emos_params/{city}.json` is missing, OR it's Sunday and the file is >7 days old
   - Calls `train_all_cities()` with current data directories
   - Catch and log any training errors — never let training failure block the main shadow loop

10. **Validate:** Delete one city's params file, run `--once`, verify it gets recreated.

## Dependencies

- Phase 2 is independent of Phase 1 (can be done in parallel)
- Phase 3 depends on Phase 1 (needs `train_all_cities()` to exist)
- All phases operate on the same two files but different functions — no merge conflicts

## Risks

- **MEDIUM: Overfitting on 7-8 samples.** L-BFGS-B with 5 params on 7-8 points could overfit. Mitigated by the validation gate in step 3 (reject params where fitted σ < naive σ) and by the bounds constraints in `train_emos()`.
- **LOW: Hindcast data quality.** If Open-Meteo hindcast members are reanalysis-contaminated, trained params would be overconfident. Low probability — these are documented as operational ensemble runs.
- **LOW: Archive API rate limiting.** Training fetches 8 cities × (hindcast + archive) = 16 API calls. Open-Meteo free tier allows 10,000/day. No risk at this scale.

## Acceptance

- [ ] `emos_params/` contains 8 JSON files, one per city
- [ ] Each trained model has σ wider than the naive Gaussian for that city
- [ ] `fetch_ensemble_forecast()` retries once on failure and logs warnings
- [ ] When ensemble fetch fails, `process_city()` uses last-known forecast, not 15.0°C
- [ ] Auto-retrain fires when params are missing
- [ ] Existing shadow tracking (market fetch, METAR, trade logging, resolution) still works — no regressions
- [ ] `--train` CLI command works as a standalone one-shot

## Verification Plan

- **Phase 1:** Run `--train`, read each `emos_params/{city}.json`, confirm `trained_on >= 7` and that the implicit σ from `(d, e)` params exceeds the naive σ. Spot-check one city's bin probabilities before and after calibration.
- **Phase 2:** Simulate a fetch failure (bad URL or network timeout), verify warning log and last-known fallback behavior. Restore URL and confirm normal operation resumes.
- **Phase 3:** Delete `emos_params/seoul.json`, run `--once`, confirm it's recreated. Run again and confirm it's NOT retrained (not Sunday, file exists and is fresh).
