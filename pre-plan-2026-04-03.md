# Pre-Plan Brief — Asian Weather Bundle A: Calibration + Fetch Resilience

## Work Snapshot

**Chosen work:** Fix the three foundational gaps from discovery pass 1 — train EMOS params, add forecast fetch resilience, and replace the 15°C hardcoded default. These are discovery findings #1, #2, and #3.

**Why now:** The shadow tracker has been running for 4 days with uncalibrated probabilities. Every day of uncalibrated operation produces misleading P&L data that poisons the kill/promote gate evaluation. The tracker can't produce trustworthy validation metrics until probabilities are calibrated.

**Artifacts:** Discovery summary at `Projects/Prediction-System/discovery-pass-1-asian-weather-2026-04-02.md`. Code at `run_asian_weather_shadow.py` and `src/calibration/emos.py`.

## Verified Context

**Training data available:**
- 16 matched forecast→resolution pairs across 3 resolved days (local files)
- Per city: 2-3 samples locally (Seoul has 3, others have 1-2)
- `train_emos()` requires >=7 samples — NO city meets this yet from local data alone

**Key API finding — hindcast ensemble data is available:**
- `ensemble-api.open-meteo.com` accepts `past_days` parameter
- Returns ~5 days of ensemble member data (Mar 30 – Apr 3 for `past_days=7`)
- 50 IFS members per day, non-null
- Combined with local forecasts: 7-8 samples per city for most cities

**Archive API works:** `archive-api.open-meteo.com` returns 30+ days of actual daily highs per city with full coverage. Seoul tested: 31/31 days with data, Mar 1-31.

**The variance problem is quantified:**
- Ensemble `ifs_var` range: 0.07–0.79 (σ ≈ 0.3–0.9°C)
- Actual forecast MAE on Day 2: 1.17°C with +0.89°C systematic low bias
- Shanghai: ensemble σ=0.32°C but actual error was 3.8°C — 12x larger than ensemble spread

## Constraints / Dependencies / Risks

- **Data constraint:** Hindcast ensemble data is only ~5 days deep. For full 30-day rolling window EMOS (the design spec target), we need to accumulate 30 days of daily forecasts. The initial training with 7-8 samples is a bootstrap — parameters will improve as data accumulates.
- **Convergence risk:** L-BFGS-B on 7-8 samples with 5 parameters could overfit. The `bounds` in `train_emos()` constrain this somewhat. Mitigation: validate trained params produce wider σ than naive Gaussian before accepting them.
- **Hindcast vs live assumption:** If the Open-Meteo hindcast ensemble members are reanalysis-contaminated (fit to observations after the fact), the training data would be cleaner than reality, producing overconfident EMOS params. Low probability — Open-Meteo documents these as operational forecasts, not reanalysis.
- **No sensitive surfaces** detected (no auth, payments, PII, or public endpoints).

## Approach Options

### Approach 1: Bootstrap EMOS from hindcast + archive, auto-retrain trigger

**Core idea:** Fetch 5 days of hindcast ensemble data + 30 days of archive actuals per city. Assemble training pairs where both exist. Train EMOS immediately for cities with >=7 pairs. Add an auto-retrain trigger to `run_once()` that retrains weekly as data accumulates. Fix fetch reliability and default fallback separately.

**Why it could work:** The `train_emos()` function already exists with proper CRPS minimization. The hindcast API is verified working. This gives EMOS params immediately rather than waiting 4+ more days.

**Main tradeoff:** 7-8 samples is thin — EMOS params may overfit. Mitigation: validate that trained σ is wider than naive σ before accepting.

**Fastest validation:** Run `train_emos()` once for Seoul (3 local + ~5 hindcast = ~8 samples) and check whether the fitted params produce wider variance than the naive Gaussian.

**Better fit when:** You want to fix the probability quality issue immediately rather than waiting for more data to accumulate naturally.

### Approach 2: Wider interim variance floor + deferred training

**Core idea:** Skip EMOS training for now. Use the archive API to compute empirical daily-high variability per city over 30 days, then set `max(naive_std * 1.3, archive_empirical_std)` as the variance floor. Train EMOS later once 14+ natural samples accumulate.

**Why it could work:** Simpler, no hindcast assumption, and the archive-based variance floor directly measures what we care about (how much daily highs vary at each station). Addresses the underdispersion immediately.

**Main tradeoff:** Archive std measures daily variability (weather variability), not forecast error. A station with stable weather could have low archive std but still have large forecast errors. Also doesn't fix the mean bias — only the spread.

**Fastest validation:** Fetch archive std for Shanghai (the worst-performing city) and compare against observed forecast error.

**Better fit when:** You distrust the hindcast data quality or want a zero-risk interim fix.

## Recommended Path

**Approach 1: Bootstrap EMOS from hindcast + archive, auto-retrain trigger.**

Causal chain trace:
1. Build a `train_all_cities()` function that fetches hindcast ensemble + archive actuals → assembles `TrainingSample` list → calls `train_emos()` → saves params to `emos_params/{city}.json`
2. `process_city()` already checks `if emos_params:` → `emos_predict()` — no change needed on the consumption path
3. Bin probabilities immediately become wider and better calibrated → NO-harvesting stops classifying near-boundary bins as "impossible" → fewer catastrophic NO losses
4. The shadow tracker produces trustworthy accuracy and P&L metrics → the kill/promote gate can make real decisions in 10 more days

The chain holds. Every step produces a concrete, observable improvement. The end result (trustworthy validation metrics) directly serves the user's goal of knowing whether the Asian weather edge is real.

**Why not Approach 2:** The archive variability floor is a band-aid that fixes spread but not bias. EMOS fixes both (parameter `a` absorbs mean bias, parameters `d`+`e` fix spread). Since the EMOS code already exists and the data is available, the incremental cost of doing it right is small.

**Three concrete changes:**
1. **New function `train_all_cities()`** in emos.py: fetch hindcast ensemble (`past_days=7`) + archive actuals (45 days) for each city, assemble matched pairs, call `train_emos()`, save params. Add to CLI as `--train`.
2. **Forecast fetch resilience** in emos.py `fetch_ensemble_forecast()`: add 1 retry with 5s backoff, log failures explicitly. In `run_asian_weather_shadow.py` `process_city()`: replace 15°C default with last-known forecast from the previous day's file.
3. **Auto-retrain trigger** in `run_once()`: if today is Sunday or emos_params are missing, call `train_all_cities()`. Uses archive + all accumulated local data (growing pool).
